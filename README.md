# Expense Anomaly Agent

An AI agent that ingests expense/invoice records, checks them against policy
rules and historical patterns, and either auto-approves, flags for human
review, or asks a clarifying question — with a self-verification step and
hard-coded guardrails on top.

Built as a take-home project for a Senior Applied AI Engineer interview.

## Dataset

`expenses.json` has 40 records: mostly straightforward cases (so the eval
isn't gamed by an agent that just flags everything) plus a dozen
deliberately tricky edge cases — borderline policy thresholds, first-time
vendors at different amounts, a possible duplicate, missing receipts
above/below the receipt-required threshold, a suspiciously round number, a
hard-ceiling breach, a category/description mismatch, and a missing
required field.

`ground-truth.json` in `eval/` has the expected action (`approve` / `flag`
/ `clarify`) and reasoning for each record. One label (`EXP004`) was
corrected mid-build after the eval harness itself surfaced a genuine
authoring mistake — a $95 meal mislabeled "approve" that actually exceeds
the $75 meals policy limit. The agent's own policy check caught it before
a human review did.

## How the agent works

1. **Perceive** — the agent receives one expense record.
2. **Reason** — it calls whichever of the four read-only tools are
   relevant (policy check, vendor history, employee pattern, duplicate
   check) and reads the free-text description itself for signals no tool
   can catch (e.g. a personal purchase misfiled under a business category).
3. **Act** — it concludes `approve`, `flag`, or `clarify`. A `flag` or
   `clarify` conclusion requires it to have actually called the matching
   action tool during reasoning.
4. **Verify** — before the decision is returned, code-level guardrails
   re-check it independently of the model's own reasoning:
   - Hard ceiling: never let "approve" through above the configured
     dollar ceiling, regardless of what the model concluded.
   - Policy disagreement: if the deterministic policy check found a
     violation but the model said "approve" anyway, downgrade to "flag".
   - Action enforcement: if the model claimed "flag" or "clarify" but
     never actually called the corresponding tool, the code calls it
     instead of trusting the claim.

This means the model's own judgment is never the last word — every
decision either matches a guardrail-verified conclusion or gets
overridden with a clear, logged reason.

## API

- `GET /api/health` — liveness check
- `GET /api/expenses` — all 40 expense records, with vendor and employee names joined in
- `POST /api/evaluate/:id` — runs the full agent loop on one expense, returns its decision

## Running locally

\`\`\`bash
# Terminal 1
cd backend
npm install
cp .env.example .env   # add your ANTHROPIC_API_KEY
npm run dev

# Terminal 2
cd frontend
npm install
npm run dev
\`\`\`

Backend: http://localhost:3001
Frontend: http://localhost:5173 (dev server proxies `/api/*` to the backend)

Open the frontend in a browser. Click **Evaluate** on any row to run the
agent on that expense, or **Run Agent on All** to evaluate all 40
sequentially and watch decisions land one at a time. Click a decision
badge to expand the model's reasoning and risk factors.

## Testing without the UI

\`\`\`bash
cd backend

# Sanity-check the deterministic tools against the tricky records
npx tsx src/tools/manual-test.ts

# Run the agent on a single expense from the terminal
npx tsx src/agent/run-single.ts EXP038

# Run the full eval harness (costs real API calls — try --limit first)
npx tsx src/eval/run-eval.ts --limit 5
npx tsx src/eval/run-eval.ts
\`\`\`
